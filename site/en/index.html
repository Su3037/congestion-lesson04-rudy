RUDY congestion estimate

After placement and before routing, how do you find out quickly where wires will crowd? RUDY spreads each net's wirelength evenly over the routing tiles under its bounding box, sums the nets into a demand map, and compares each tile with its capacity. This lesson starts from one net, builds the full six-net map, and ends with two congestion statistics that disagree.

Model boundary. The main line is the teacher's discrete equal-share model P: each net's HPWL is divided by the number of selected tiles and added equally to each. It is not the continuous, area-based density of the DATE 2007 paper, and it is not a router. For comparison, a separate model A (by overlap area) is always labelled as such and has been checked against DREAMPlace and OpenROAD source code. Demand and capacity share one set of teaching units; they are not routing tracks.

Terms first

Pin
A point that must be connected. Here a pin is a coordinate (x, y) on the chip.
Net
A set of pins that must be connected together. There are 6 nets; one has 4 pins.
Bounding box (bbox)
The smallest axis-aligned rectangle containing all of a net's pins.
HPWL
Half-perimeter wirelength: box width + box height, a quick estimate of the net's wirelength.
GCell
A coarse routing tile. The 12 × 8 chip is cut into 4 columns × 2 rows of 3 × 4 tiles.
Demand
Estimated routing in a tile, stored as demand[x][y]: column first, then row.
Capacity
What a tile can hold. Default C = 2, in the same teaching units as demand.
Ratio
Demand ÷ capacity. Above 1 means over capacity.
Overflow
max(0, demand − capacity): only the excess, never negative.
Hotspot
The tile with the highest demand or ratio. Max overflow measures how bad the worst hotspot is.

Reading: from one net to the full demand map

1. Total wirelength hides location

This is the teacher's spread placement: six pins, six nets. Dashed lines show which pins connect, not routes. The six nets' HPWL adds up to 34, but the same 34 could be packed into one spot or spread across the chip. Whether routing fails depends on where it crowds.

2. One net: box, HPWL, selected tiles

Take net A–B. Its box runs from x=1 to x=8 with zero height, so HPWL = 7 + 0 = 7. The left end is in column 0, the right end in column floor(8/3) = 2. The teacher's rule: find each corner's tile, then select every tile between them, inclusive. That gives (0,0), (1,0), (2,0), and each receives 7 ÷ 3 = 7/3 ≈ 2.33.

3. Boundaries: a pin exactly on a tile edge

floor(3 / 3) = 1, so a point at x = 3 belongs to column 1. A net from (1,1) to (3,1) therefore selects two tiles, 1 each, even though column 1 overlaps the line by zero length. This is the endpoint-tile rule, not area intersection. Drag a pin across a tile edge in the lab and the selection jumps; that is the rule, not a glitch. Coincident pins give HPWL = 0 and a zero share: no invented demand and no division by zero.

4. Add the nets one by one

Every computation starts from a zero matrix and adds the six nets' shares in turn:

The eight tiles sum to exactly 34, the total HPWL. In model P this always holds: each net's HPWL is handed out in full to its tiles.

5. Capacity changes ratio and overflow only

At C = 2, six tiles overflow: total overflow 22, max 14/3 ≈ 4.67. Set C = 1 and not one demand number changes; only ratio and overflow do: total 28, max 17/3, still six tiles.

6. Two statistics disagree

The teacher also gives a centre-cluster placement: every pin sits in tile (1,0), so all demand lands in one tile, 7. Both maps use one fixed legend: the same colour means the same value. This lesson never rescales each map to its own maximum.

So the spread is not "better overall". It makes the single worst tile slightly better and spreads the burden over six tiles. There is a deeper reason too: in model P total demand equals total HPWL, so total overflow largely measures wirelength. Name the metric before saying "better".

7. A different RUDY changes the conclusion

Real tools (DREAMPlace's rudy op, OpenROAD's grt::Rudy) share by overlap area: a tile gets HPWL × overlap area ÷ box area. That is this lesson's model A. On the same spread placement, model A's max overflow is 5.54, higher than the cluster's 5. Under model A even max overflow favours the cluster. RUDY is a family of methods; say which one you use.

8. Limits

  • RUDY is a fast pre-routing estimate, not a routing result, and certainly not manufacturability sign-off.
  • Real capacity is split by direction and by metal layer; DREAMPlace produces separate horizontal and vertical maps.
  • Multi-pin nets are longer than their HPWL. RISA (Cheng, ICCAD 1994) scales by pin count, e.g. 1.0828 for 4 pins; neither model P nor model A applies it.
  • How well it predicts congestion has to be measured against a router (e.g. per-tile Spearman correlation); the Checks section describes how.

Pseudocode (model P)

1  demand ← zero matrix [nx][ny]          # every computation starts fresh
2  for each net:
3    box ← bounding box of its pins
4    hpwl ← box width + box height         # line nets valid; 0 for coincident pins
5    tiles ← every tile between the corner tiles, inclusive   # floor, then clamp
6    share ← hpwl ÷ |tiles|                # divide by tile count, not by area
7    for t in tiles: demand[t] += share
8  overflow[t] ← max(0, demand[t] − C)     # C must be > 0; capacity never changes demand

Input is validated first: unknown pins, empty nets, non-finite or off-chip coordinates, a grid that does not tile the chip, and capacity ≤ 0 are rejected with a reason, instead of producing NaN or a reassuring all-zero map.

How we know the numbers are right

The numbers are not checked only by their author. oracles/ and tests/ in the repository rerun on every build:

  • The teacher's own code: unmodified congestion-core.js and solvers.py versus model P on 5000 + 1000 generated cases: 0 mismatches.
  • Exact fractions: the Python reference uses fractions.Fraction; the example equals 37/6, 14/3, 25/6, 20/3 exactly.
  • Real tools' code: the RUDY kernels copied verbatim from DREAMPlace (4adf954) and OpenROAD (7b26270), compiled and compared tile by tile with model A: 1489 and 739 cases, 0 mismatches.
  • Property tests: fast-check and Hypothesis check conservation, capacity independence, net-order independence, linearity and mirror symmetry (for model P only off tile edges).
  • JS versus Python: 2000 cases with random grids, non-integer and boundary coordinates, line nets, coincident pins and malformed input: 0 mismatches.

How the implementations differ on edge cases is in docs/edge-cases.md: a horizontal line net, for example, gets a positive value in model P, 0 in DREAMPlace, and is skipped by OpenROAD.
